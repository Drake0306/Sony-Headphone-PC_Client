## Q1. What is the project, what is the current version/release, and is development active or stalled?

### Takeaway
SonyHeadphonesClient is an MIT-licensed C++/Dear ImGui desktop app (Windows/macOS/Linux) that reverse-engineers the Sony Headphones Connect Bluetooth protocol so WH-1000XM3-era headsets can be controlled from a PC. It is **dead upstream**: last release v1.3.2 (2023-04-26), last commit 2025-07-19 (README-only), and the repository was **archived (read-only) on 2025-07-19**; the author directs users to forks, chiefly mos9527/SonyHeadphonesClient.

## Q2. Which headphone models are supported and which are not?

### Takeaway
Officially: WH-1000XM3 ("fully works"), WH-1000XM4 ("partially works"), MDR-XB950BT ("fully works"). Community reports in issue #29 add WF-1000XM3, WH-1000XM2, WI-1000XM2, WH-XB900N, WH-CH700N, WH-N910H, MDR-XB950N1 (VPT only) as working. **Not supported**: everything using Sony's newer "mdr.link2"/MDR v2 protocol and different service UUIDs — WF-1000XM4, WH-1000XM5, WF-1000XM5, LinkBuds S, WH-CH720N, WH-CH520, WH-CH510, WH-XB910N, WF-C500, WF-C700N — all fail with "Couldn't connect: 10049" / "could not connect to bluetooth socket" / "connection timed out". ### Inferences
- The supported set is exactly the Sony "MDR v1" protocol generation (c. 2017–2020 devices: XM2/XM3/XM4 over-ears, WF-1000XM3, XB900N/XB950, CH700N, N910H). Anything launched from mid-2021 onward (WF-1000XM4 and later, including XM5/XM6, LinkBuds, CH720N, C700N) uses MDR v2 with per-model service UUIDs and is unreachable by this client.
- WH-1000XM4 is "partial" because of intermittent "Invalid checksum!" disconnects and because XM4-only features (Speak-to-Chat, multipoint, ANC optimizer) were never merged (see PR #103 in Q3).

## Q3. Which features exist vs. what is missing compared with Sony Sound Connect / Headphones Connect?

### Takeaway
The client implements only four settings — Ambient Sound Control level (0–19 slider) with "Focus on Voice", an NC/ASM on-off toggle, Sound Position presets and Surround/VPT presets — all **write-only**. It does **not** read device state, show battery, codec, or do EQ, Speak-to-Chat, multipoint, touch-sensor, DSEE, auto power-off, or firmware updates. PRs for EQ presets (#66) and XM4 Speak-to-Chat/ANC optimizer/multipoint (#103) were never merged.

### Cited Findings

### Inferences
- Compared with Sony Sound Connect, the client lacks: battery/case battery, codec indicator, EQ/Clear Bass, DSEE, Speak-to-Chat, Adaptive Sound Control, multipoint device management, pairing mode, touch-sensor/button assignment, auto power-off, wear detection/pause, voice guidance, Bluetooth connection-quality mode, 360RA/head tracking, firmware updates, and all cloud/account features. - "Write-only with ACK" design means if the phone app changes a setting, the PC client is unaware.

## Q4. Code architecture: how does it talk to the headphones?

### Takeaway
A single C++20 executable: a platform-agnostic core (`CommandSerializer` framing, `BluetoothWrapper` send/ACK sequencing, `Headphones` state) plus an `IBluetoothConnector` interface implemented per OS over Bluetooth Classic RFCOMM/SPP (Winsock `AF_BTH` on Windows, BlueZ `BTPROTO_RFCOMM` + D-Bus on Linux, `IOBluetoothRFCOMMChannel` on macOS). GUI is Dear ImGui (Win32+DirectX 11 on Windows, GLFW+OpenGL3 on Linux) and a native Cocoa storyboard app on macOS. Protocol is Sony "MDR v1" over the SPP service UUID 96CC203E-5068-46ad-B32D-E316F5E069BA.

### Cited Findings
- Source layout under `Client/`: `BluetoothWrapper.{h,cpp}`, `ByteMagic.{h,cpp}`, `CommandSerializer.{h,cpp}`, `Constants.h`, `CrossPlatformGUI.{h,cpp}`, `Exceptions.h`, `Headphones.{h,cpp}`, `IBluetoothConnector.h`, `SingleInstanceFuture.h`, `TimedMessageQueue.{h,cpp}`, `CascadiaCodeFont.cpp`, `Fonts/`, plus `windows/{WindowsBluetoothConnector,WindowsGUI,main}.cpp`, `linux/{DBusHelper,LinuxBluetoothConnector,LinuxGUI,main}.cpp` + `FindDBus.cmake`, `macos/{AppDelegate.mm,ViewController.mm,MacOSBluetoothConnector.mm,main.mm,Main.storyboard,SonyHeadphonesClient.xcodeproj,...}`; `imgui` is a git submodule of ocornut/imgui. — [Git tree](https://github.com/Plutoberth/SonyHeadphonesClient/tree/master/Client); [.gitmodules](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/.gitmodules)
- Wire framing (comment in `CommandSerializer.h`): "Serialized data format: `<START_MARKER>ESCAPE_SPECIALS(<DATA_TYPE><SEQ_NUMBER><BIG ENDIAN 4 BYTE SIZE OF UNESCAPED DATA><DATA><1 BYTE CHECKSUM>)<END_MARKER>`"; references to the decompiled Android classes `CommandBluetoothSender.sendCommandWithRetries` and `BluetoothSenderWrapper.sendCommandViaBluetooth`. START_MARKER = 62 ('>'), END_MARKER = 60 ('<'), MAX_BLUETOOTH_MESSAGE_SIZE = 2048, checksum = byte sum. — [Client/CommandSerializer.h](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/CommandSerializer.h); [Client/Constants.h](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/Constants.h)
- `DATA_TYPE` enum mirrors Sony's: DATA=0, ACK=1, DATA_MC_NO1=2, DATA_ICD=9, DATA_EV=10, DATA_MDR=12, DATA_COMMON=13, DATA_MDR_NO2=14, SHOT=16 ... LARGE_DATA_COMMON=45. NC/ASM enums: `NC_ASM_INQUIRED_TYPE`, `NC_ASM_EFFECT`, `NC_ASM_SETTING_TYPE`, `ASM_SETTING_TYPE`, `ASM_ID {NORMAL, VOICE}`, `NC_DUAL_SINGLE_VALUE`. — [Client/Constants.h](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/Constants.h)
- `BluetoothWrapper` (thread-safe, owns a `unique_ptr<IBluetoothConnector>`) exposes `sendCommand(bytes)`, `connect(addr)`, `disconnect()`, `getConnectedDevices()`, keeps `_seqNumber`, and `_waitForAck()` after each send. — [Client/BluetoothWrapper.h](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/BluetoothWrapper.h)
- `IBluetoothConnector` interface: `send`, `recv`, `connect(addrStr)`, `disconnect`, `isConnected` (must be thread-safe), `getConnectedDevices()`; `SONY_UUID = "96CC203E-5068-46ad-B32D-E316F5E069BA"`. — [Client/IBluetoothConnector.h](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/IBluetoothConnector.h)
- Windows backend: Winsock2 `WSAStartup`, `SOCKADDR_BTH{addressFamily=AF_BTH, serviceClassId=UuidFromString(SONY_UUID), btAddr}`, `::connect/::send/::recv`; device enumeration via `BluetoothFindFirstRadio`/`BLUETOOTH_FIND_RADIO_PARAMS`. Error "Couldn't connect: 10049" is `WSAEADDRNOTAVAIL` from this `connect()` call. — [Client/windows/WindowsBluetoothConnector.cpp](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/windows/WindowsBluetoothConnector.cpp)
- Linux backend: `socket(AF_BLUETOOTH, SOCK_STREAM, BTPROTO_RFCOMM)` with `RFCOMM_LM_AUTH | RFCOMM_LM_ENCRYPT`, `read`/`write`; D-Bus (`DBusHelper`) used to enumerate connected BlueZ devices; requires `libbluetooth-dev libglew-dev libglfw3-dev libdbus-1-dev`. — [Client/linux/LinuxBluetoothConnector.cpp](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/linux/LinuxBluetoothConnector.cpp); [README](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/README.md)
- macOS backend (Objective-C++): `IOBluetoothDevice getServiceRecordForUUID:` → `getRFCOMMChannelID` → `IOBluetoothRFCOMMChannel` with an `IOBluetoothRFCOMMChannelDelegate` that pushes received bytes into a mutex/condvar-protected queue; `writeSync` for sends. — [Client/macos/MacOSBluetoothConnector.mm](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/macos/MacOSBluetoothConnector.mm)
- GUI: Windows uses `imgui_impl_win32` + `imgui_impl_dx11` (`d3d11.h`, DirectInput); Linux uses `imgui_impl_glfw` + `imgui_impl_opengl3` with GLEW; macOS uses an Xcode project with `Main.storyboard`, `AppDelegate.mm`, `ViewController.mm` (CMake sets `DEAR_IMGUI` only for WIN32 OR LINUX). — [Client/windows/WindowsGUI.h](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/windows/WindowsGUI.h); [Client/CMakeLists.txt](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/Client/CMakeLists.txt)
- Build: CMake ≥3.1, `CMAKE_CXX_STANDARD 20`; Windows requires VS 2022 + Windows SDK; macOS via the provided xcodeproj. Users getting `VCRUNTIME140_1.dll was not found` must install the MS VC++ Redistributable. — [README](https://github.com/Plutoberth/SonyHeadphonesClient/blob/master/README.md)
- Protocol-sniffing guidance for contributors is a comment by @guilhermealbm linked from the README (PR #36). — [PR #36 comment](https://github.com/Plutoberth/SonyHeadphonesClient/pull/36#issuecomment-795633877)
- A Qt port was planned ("Cross-platform build system in preparation for Qt port" in v1.2 notes; open issues #56 "Qt Deployment", #91 "Qt Layouts", #92 "Qt Virtual Sound Backend"; @Tatsh mentions "my Qt version" in #27) but never shipped. — [v1.2 release](https://github.com/Plutoberth/SonyHeadphonesClient/releases/tag/v1.2); [Issues](https://github.com/Plutoberth/SonyHeadphonesClient/issues)

### Inferences
- Only one command is in flight at a time (`SingleInstanceFuture<void> _sendCommandFuture`), which @Tatsh credited for the ImGui version being more reliable than his Qt build regarding the checksum bug.
- Because the UUID and command set are compile-time constants, adding MDR v2 devices requires structural changes, which is why forks rewrote rather than patched.

### Gaps
- No architecture document or protocol spec exists upstream beyond code comments; the most complete MDR v1 protocol write-up referenced is V02460's gist (https://gist.github.com/V02460/f87ed1f6e4ccb9baef1c14620b7f088d), not fetched here.

## Q6. Notable forks that continue the project

### Takeaway
The de-facto successor is **mos9527/SonyHeadphonesClient** (345 stars, 50 forks, 23 contributors, last push 2026-11-06, 22 releases, latest 1.4.4 on 2025-09-27 with active `rewrite`/`v1-compat` branches), which re-implements the protocol as a library (`libmdr`) supporting MDR v2 devices (WF/WH-1000XM5, XM6, LinkBuds, CH720N, C510/C700N) and runs on Windows/Linux/macOS/iOS/Android/Web(WASM)/HarmonyOS. It is technically **not a GitHub fork** (fork flag false; recreated repo) though it credits Plutoberth. Direct forks of Plutoberth's repo are small (≤7 stars): pasical (WH-XM5, archived), aybruh00 (XM4 features), semvis123, someconfusednoises/SonySoundConnectClient. Separate non-fork projects: czcqty/SonyHeadphonesClient (Qt Quick, uses libmdr, 0 stars, created 2026-08-10) and whitebeard10/SonyCompanionApp (Windows-only).

## Q7. What do users complain about (issues, Reddit, HN)?

### Takeaway
The dominant complaint by far is **"Couldn't connect: 10049" / "could not connect to bluetooth socket" / "connection timed out" on any post-2021 Sony device** (WF-1000XM4, XM5, LinkBuds S, CH720N, etc.), followed by: no Speak-to-Chat toggle (the #1 wanted feature for XM4/XM5 owners on PC), no EQ, no state readback/battery, intermittent "Invalid checksum!" disconnects on XM4, Linux Wayland/GLEW "Failed to initialize OpenGL loader!" crashes and missing shared libraries, antivirus false positives on the Windows exe, and the hands-free-profile audio switching problem (not fixable by the app). No Reddit or Hacker News threads about the project were found by search.
