Advanced equalizer

Can Hairline give the ULT WEAR a many-band equalizer, and would it save to the headphones? Research note, 8 November 2026.

Short answer. The headphones can only store six numbers: Clear Bass and five fixed bands at 400 Hz, 1 kHz, 2.5 kHz, 6.3 kHz and 16 kHz, each in 21 steps. There is no command on this model that accepts more bands, so a 10-band or 31-band curve cannot be saved to the headphones. It can run in the app, as a system-wide equalizer on the Mac, but only after installing a signed audio driver with your password. That is a real project, not a screen.

Recommendation. Build the full-area Advanced view you described, with two honest outputs: a "Send best fit to headphones" button that squashes the curve onto the six device bands and saves it, and an "App EQ" switch that applies the full curve on this Mac only, with the label you asked for. Ship the view and best-fit first (small); make the in-app audio engine its own phase (large).

What the headphones can hold

This comes from the unit itself, not from a review. On connect Hairline asks for the EQ capability and the headphones answer 51 03 06 15 0A 0C: six bands, 21 steps each, an extra step for ULT 2, twelve preset ids. Band 0 is Clear Bass, the other five sit at fixed centres. The write command 58 03 carries exactly those six values plus the preset id and the ULT level, and nothing else. Two of the preset ids are user slots, which is where a custom curve lives on the device.

So the honest UI rule is simple: anything with more than six controls is an app setting. The Advanced view must say so, in the view, not in a tooltip.

Three ways to use a bigger curve

A. Best fit to the device saves to headphones

Take the many-band curve, evaluate it at the six device centres, round to the 21 steps, and write it with the normal EQ command. The headphones then carry it to your phone and everywhere else. It is lossy: a narrow 3 kHz dip becomes a shallow dip at 2.5 kHz. The view shows the fitted six values beside the full curve so the loss is visible. This costs a day of work and adds no new wire commands.

B. In-app EQ on this Mac app only

To equalize what you hear, the app has to sit between the Mac's audio and the Bluetooth link. macOS gives no way to do that from a normal app; every system equalizer (eqMac, SoundSource, BlackHole-based setups) installs a virtual audio device, an Audio Server plug-in in /Library/Audio/Plug-Ins/HAL. The app makes that device the system output, reads the audio back from it, runs the filters, and plays the result to the headphones. What it takes:

  • A driver bundle written against Apple's Audio Server Plug-in API (Apple ships a null-driver sample; eqMac's open-source driver started from it). It runs in user space, not the kernel, so it is stable, but it is still a separate binary.
  • Developer ID signing. Community projects report that macOS 15 and later silently skip ad-hoc signed drivers, so this needs the paid Apple Developer Program and a proper signature, plus notarization if we distribute it.
  • Admin install. Copying into the HAL folder and restarting coreaudiod needs your password once. eqMac asks for it on first launch for this reason.
  • Routing logic. Switch the default output to the virtual device while the headphones are connected, hand audio back when they disconnect or the app quits, keep volume keys working, and never leave the Mac silent if the app crashes. This is where such apps earn their bug reports.
  • The filters themselves are the easy part: a chain of biquads or Apple's own EQ audio unit, any number of bands, a few milliseconds of buffer on top of the normal Bluetooth delay.

Effects: only audio from this Mac is equalized. Your phone hears the headphones' own six bands. Videos gain a little lip-sync offset from the buffer. CPU and battery cost is negligible.

C. Both, side by side recommended

The Advanced view holds one curve. Two actions sit under it: Send best fit to headphones (option A, always available) and App EQ on this Mac (option B, a switch that is greyed out with a note until the engine phase ships). The label you asked for reads, in the view: These bands run in Hairline only. The headphones keep their six-band curve; use "Send best fit" to put the closest match on them.

Is it worth it?

Option A is worth it on its own: a big, comfortable editor for the six values you already have, plus a many-band curve to design from, saving to the headphones. Small, safe, no driver.

Option B is the thing people actually pay for in SoundSource and eqMac, so yes, it is useful, but only for listening from the Mac, and it adds a driver, a signing cost, a password prompt and a new class of audio bugs to a project that has had none so far. My advice is to decide on it after the view exists and you have used the best-fit path for a week. If you still want it, it gets its own phase with the driver as its first task, and it should be an opt-in install inside Settings, never part of the normal launch.

The view, as you described it

An "Advanced" button beside the equalizer on the Sound screen. It takes over the whole viewable area of the window (not full screen), with a back button at the top left. Four big faders are visible at a time, the same fader as today but taller. Under them a band strip shows all bands with the visible four marked; left and right buttons step through four at a time, since dragging a strip reads badly with a mouse. The default set is ten bands from 31 Hz to 16 kHz, like Sony's newest headphones; a 31-band third-octave set can be a choice in the same view later.
